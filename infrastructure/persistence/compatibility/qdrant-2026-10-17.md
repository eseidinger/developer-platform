# Qdrant provider verification — October 17, 2026

Pinned Qdrant server/bundled dashboard: `qdrant/qdrant:v1.19.2` at
`sha256:b7b0444c4c351c970b98e90a6f89c2ee4287c65b44e52b4cb503fa5b2aa927ad`.
Server and Web UI use Apache-2.0. This is disposable local native-provider
evidence, not deployed integration or recovery acceptance.

Each resource UUID maps to one collection. The create request accepts bounded,
immutable vector dimensions and distance in `configuration`; defaults are 384
dimensions and Cosine. API/portal/catalog and recovery manifests preserve those
settings. Operators must not silently recreate a missing or mismatched retained
collection during recovery.

Native HS256 JWTs grant only that collection's `r` or `rw` permission and carry
the credential generation's expiry and identity. Each token also requires an
operator-owned validation point identifying that exact generation and resource.
Deleting the point revokes native access; data users cannot read or update the
validation collection. Signing/admin keys never appear in user credentials.

`scripts/verify/stores/verify-qdrant.py` passed against the pinned real server:

- Two collections, independent resource mapping, repeatable provisioning and
  issuance, filtered nearest-neighbor retrieval and scoped collection listings.
- Writer point and payload-index changes; reader queries; denial of reader
  writes/schema changes, foreign collection access, resource deletion, arbitrary
  collection creation and validation-record access.
- Native JWT expiry and immediate per-generation revocation, including repeated
  cleanup. Expired tokens were tested beyond the server's documented 30-second
  clock leeway; the outer relay separately enforces the exact lease deadline.
- Real HTTP relay access and rejection of a subsequent request after expiry,
  independently of the cleanup worker or the server's JWT clock tolerance.
- Native disk-file usage from `/collections/{name}/memory`, using
  `result.total.disk_bytes`; no estimate from point counts or fake zero.
- Isolated collection purge with the unrelated collection retained.

The fixture binds only loopback and uses plain HTTP inside its temporary setup.
Production routing/network/TLS and browser-session acceptance are not
established by that fixture. Byte admission/monitoring is advisory at this
checkpoint; native vector/payload limits and physical overhead must not be
conflated with a hard resource byte quota. gRPC transport is not provided by the
HTTP lease relay.
