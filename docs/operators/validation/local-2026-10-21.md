# Local validation: October 21, 2026

The Linux/WSL installation was deployed with PostgreSQL, RustFS S3, Qdrant,
OpenSearch with Dashboards, and the Neo4j controller enabled. Neo4j instances
are provisioned per resource. Disposable test applications and human identities
were used; the initial administrator's temporary password was not consumed.

## Results

- **AI**: A real model request and a deployed `explain_application` run
  completed. API and CLI history returned the saved run; Chromium displayed its
  result and evidence. Reported estimated run cost: USD 0.004542.
- **API and CLI**: A pinned application deployed and became ready. All five
  named store resources became active and accepted separate human grants.
- **Portal**: Real OIDC login, project navigation, AI history, evidence, and
  the five-provider resource catalog passed in Chromium.
- **Native consoles**: RustFS, Qdrant, OpenSearch Dashboards, and Neo4j Browser
  passed scoped operations with two users and active console revocation. Neo4j
  Community grants both users full database access; a read-only Neo4j role is
  not claimed.
- **PostgreSQL console**: Deployed pgAdmin OIDC, Query Tool DDL/write/read,
  reader write denial, user isolation, password-save denial, and active-query
  revocation passed.
- **Lifecycle**: Provisioning, edge routing, configuration
  concurrency/replacement/drift, secret
  adoption/rotation/revert/confirmation/redaction, failed-pod logs,
  authorization, audit, and retirement passed.
- **Hosted access, host-side subset**: 26 assertions passed, including human
  approval and bounded claim refresh, secure cookies, CSRF, stable identity,
  machine authorization denials, explicit database bindings and persistence
  after restart, policy rollback, normal/emergency credential rotation, and
  revocation with existing sessions/tokens. This subset declared no workload
  outbound access and does not establish workload-to-public HTTPS.
- **Provider components**: Existing isolated PostgreSQL, RustFS, Qdrant,
  OpenSearch, and Neo4j fixtures passed their access, isolation,
  expiry/revocation, restore, and scoped-purge assertions. PostgreSQL included
  pgvector HNSW and AGE.
- **Telemetry**: Production Alloy/Prometheus metric filtering, Loki log
  minimization and restart readback, and Alloy/Tempo trace privacy and
  parentage fixtures passed. Trace readback included 100 HTTP roots and ten
  model spans using synthetic provider responses.
- **Monitoring**: Production configuration and rule tests, hostname routing,
  protected application probes, untrusted-certificate rejection, and target
  retirement discovery passed.

Regression checks passed: 549 API tests (14 declared skips), 92 platform-runner
tests (two declared skips), 50 script tests, 52 UI unit tests, the helper test
file, and 30 UI browser scenarios. UI contract, lint, formatting, types, and
production build passed. Changed YAML, shell, Markdown, and Caddy configuration
were checked with their repository tools. Existing Ruff findings remain in
`app/stores/console.py` and `tests/platform/harness.py`; this work added none.

## Corrections made

- Repaired blank-secret initialization, protected Tempo mount detection, and
  noninteractive initial administrator setup.
- Used Caddy's internal CA for local application/console HTTPS and supplied only
  its public certificate to isolated pgAdmin for verified OIDC discovery.
- Established a console-origin handoff document before navigating with a Strict
  session cookie, supporting different portal and application sites.
- Required explicit deployment origins in browser helpers and used each Qdrant
  collection's actual vector dimension.
- Updated lifecycle checks for explicit named-store bindings, made the trace
  fixture independent of Alloy indentation, and refreshed retirement scope
  during asynchronous fixture cleanup.

## Boundaries

This is local functional evidence, not completion of the full acceptance gate.
The installation retains default-deny workload egress. The complete hosted
application suite requires explicitly approved outbound HTTPS destinations;
its workload-to-public HTTPS and network probes were not verified locally.
Host-side hosted-access checks are recorded separately in private runtime
reports and must not be confused with that complete scenario.
The hosted subset used the earlier cleanup implementation in its running
process, so its report records a final cleanup failure despite passing all 26
assertions. Cleanup was subsequently rerun with the scope-polling correction;
the original failure evidence is retained.

AI incident investigation and model-produced rollback proposal, approval, and
execution were covered by regression/browser fixtures, not by live provider
acceptance. The live AI result above establishes explanation and history only.

Off-host backups, remote firewall reachability, shared-service outage drills,
and elapsed retention/expiry periods were not established by this run. The
isolated restore fixtures do not prove an off-host backup of this installation.
The UI build reports its existing large-bundle advisory.

Initial sign-in uses `https://platform.localhost`. Trust the public certificate
at `.runtime/trust/local-ca.pem` in the browser, then use the username and
temporary password in private `.runtime/initial-admin.json`. Keycloak requires
a new password at first login. Runtime credentials and private test diagnostics
are excluded from commits.
