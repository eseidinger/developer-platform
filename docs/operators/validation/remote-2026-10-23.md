## Corrections and failed attempts

- Deployment telemetry previously changed every workload's pod template for each
  application operation. Desired-workload fingerprints now preserve unchanged
  workload attribution while still applying drift repairs. Real configuration,
  image, binding, schedule, scaling, and restart changes receive updated
  context. The live component run proved unchanged peers no longer roll.
- Component fixtures assumed public egress was disabled and public backends were
  directly reachable. They now test the always-forbidden private platform
  subnet, private-service connectivity, and protected public-backend denial.
  Route assertions use the current hostname-derived protected ingress name.
- Deliberately failing scheduled jobs now have bounded execution and no retries,
  so failure completes within the test's polling deadline.
- Preservation and isolation cleanup now refresh retirement scope during
  asynchronous revocation. The original preservation run passed its four
  functional assertions but failed cleanup; retirement was retried, and a fresh
  complete run passed. Earlier failed component fixtures were also retired.
- pgAdmin rejected the synthetic users' `.invalid` email domain. Only the test
  profiles were changed to reserved `example.com` addresses. Original console
  configuration and logging were restored. TLS verification stayed enabled.
- An initial Neo4j browser connection timed out. A focused retry passed both
  users and active revocation; additional safe stage diagnostics were added.
- CI exposed a gateway-fixture startup race after CA creation but before TLS
  listener activation. Verified issuer/application positive controls now wait
  within a deadline before strict route and denial assertions execute.
- The first approved PostgreSQL outage run passed the catalog and recovery
  assertions but failed fixture cleanup. Its confirmed project and persona were
  subsequently cleaned up. The drill now also verifies fresh runner token
  issuance after PostgreSQL recovery, since Keycloak shares the database and
  existing bearer tokens alone cannot prove that new authentication works. A
  fresh complete run passed, including cleanup; the failed attempt remains
  recorded separately.

## Boundaries

This is scoped remote functional evidence, not closure of the full acceptance
gate. Existing applications were checked for unchanged declarations, ready
replicas, and functioning HTTPS access boundaries; their business workflows were
not exercised with real user data.

The two approved outage drills establish identity-provider and control-plane
database recovery. PostgreSQL outage acceptance used an unbound workload;
application data continuity during a database outage remains a separate check.
Off-host backup/restore, prolonged retention and expiry windows, restricted SSH
database access, the human CLI device-login journey, and live AI proposal
approval/execution were not established. No off-host backup configuration was
found in the platform `.env`. Elapsed periods cannot be established by immediate
fixtures or a CI result.
