Community has one user database and gives native users full access. Independent
instances provide resource/project isolation; read-only requests are rejected.
Provider/resource discovery explicitly reports the full-instance capability and
native account-management power. See the
[edition comparison](https://neo4j.com/docs/cypher-manual/25/introduction/cypher-neo4j/)
and the [owner decision](../../docs/maintainers/delivery/plans/data-store-expansion.md#neo4j-community-dedicated-instance-decision).

## Identity and data paths

Each human/application generation has a separate native username and issued
secret. Native full-access users can change other native accounts. Therefore,
checking only username/native authentication would not preserve platform lease
identity. The catalog additionally records a SHA-256 verifier of the issued
platform secret; the relay checks that verifier before forwarding native LOGON.
It exposes no verifier in public credential replies. Changing another native
password cannot forge its platform secret or create/extend its lease.

The direct private path negotiates Bolt 5.4 from the client's legacy version
offers, validates all authentication/reauthentication messages and rejects
impersonation. It forwards queries unchanged. Native TLS is disabled inside the
private/SSH boundary; an opaque encrypted tunnel cannot bypass identity checks.
Client messages are limited to 1 MiB with bounded decoding depth/item counts;
16 simultaneous Bolt connections fit the shared relay's memory budget. Server
results stream in bounded chunks. SQL snapshots, hard deadlines and stale-state
checks close active sockets independently of native account cleanup.

Official Browser is served under the portal's lease cookie and uses WSS through
the same credential-bound relay. The pinned Browser omits the optional WebSocket
subprotocol header, so the adapter accepts either no subprotocol or `bolt`, still
requiring the fixed host, exact console Origin, valid human lease and Bolt payload.
Other subprotocols/providers, bad cookies and expired leases are rejected before
opening backend TCP. HTTP Query API requests independently check the same native
identity/issued-secret verifier; no operator credential is injected into data
requests. Private networks have no published ports and reject cross-instance TCP.

## Operator lifecycle and recovery

Only the operator controller receives the Docker socket. API requests select fixed
operations and UUIDs, not images, mounts, shell commands or arbitrary Cypher.
Source-IP/key checks, payload/concurrency bounds, ownership checks and request
expiry fence controller calls. Native administrator derivation uses its separate
admin key; rotating the RPC key does not change database passwords.

The controller reconciles infrastructure network attachments after Compose
recreates API/relay/controller containers. The real replacement-container fixture
verifies new IDs rejoin the owned running-instance network; stopped instances are
not restarted. Creation/count admission includes retained resources. Retirement
retains the container/volume, while confirmed purge removes only owned data and
network state. Access can be stopped and purged without a native administrator
login, including after a full-access user changed that password. Active native
administration damage requires isolated operator repair; failed cleanup remains
visible, and repeated failed generations of one resource do not monopolize cleanup
attempts for other resources.

Backups pause data leases and capture stopped native volumes, including system
identities, with an image inventory in the encrypted bundle. The restore adapter
preflights archives/inventory, creates empty labeled volumes, starts recovered
instances under catalog quarantine, revokes recovered access and refreshes endpoint
addresses before fresh approval. Latest purge intents still override older data.
Retired resources return to their stopped state. A same-version physical restore
fixture passes; this is not proof that an older binary can read migrated files.

**Restart finding:** configuring the agent with the entrypoint's repeatable
`NEO4J_server_jvm_additional` environment setting duplicated the agent configuration
on restart and prevented readiness. The reviewed image sets the agent flag once
in its configuration instead. A real clean stop took about 16 seconds with exit
code 0; restart reached readiness with one configured agent occurrence. Offline
capture must also verify the original instance restarts, not merely that its copy
can be restored. Native retirement may require asynchronous controller retries
while clean shutdown finishes.

## Monitoring and verification

Standard JVM heap, live-thread and GC observations work in Community. GC seconds
are normalized from the pinned agent's `jvm_gc_collection_seconds_sum`; an initial
custom MBean rule did not match and was removed. Docker metrics describe each
instance; relay connection counts describe data leases, not every operator-native
connection. Query latency requires explicit client histograms. The documented
[built-in Neo4j metrics exporter](https://neo4j.com/docs/operations-manual/current/monitoring/metrics/expose/)
is an Enterprise feature and is not assumed available here.

  unsupported modes, RPC/admin key separation, public verifier exclusion, WSS

- Backup tests cover restart after capture failure and fail-closed archive/image

Fixtures use synthetic data, credentials and TLS; no live installation changed.

encrypted off-host recovery throughput/RPO/RTO, host capacity and release upgrades
remain open. External domain instrumentation/comparisons are not established by
these synthetic checks.
